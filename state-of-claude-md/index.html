The state of CLAUDE.md, October 2026

We read 492 public CLAUDE.md files and counted the rules, the hooks and the settings behind them. The tables are below, and the data file is a download.

What we looked at

  • One repo per GitHub organization. We found 702 organizations by GitHub code search for coding agent rules files.
  • 667 rules files were fetched. 492 of them are CLAUDE.md (405 at the repo root, 87 under .claude/). The other 175 are AGENTS.md (150) and GEMINI.md (25).
  • Date of the run: Oct 26 2026.
  • Every column in the data file comes from public files at public URLs.

Everything below is about the 492 CLAUDE.md files unless it says otherwise.

What a model says about the rest

Most lines matched nothing, so we drew two random samples of 300 of the unmatched lines. A model (Sonnet) labeled each one DENY, CHECK, SETTING, JUDGMENT or NOT_A_RULE. DENY means a hook could block it. CHECK means a hook could check it. SETTING means a setting covers it.

Ranges are 95% margins. Sample 1 drew from 10,775 unmatched lines. After sample 1 we tightened the line detector, so it rejects code, paths, headings and fragments. That left 7,131 unmatched lines, and sample 2 is a fresh draw from them.

The tightening was tuned on sample 1, so sample 1 could be overfit. Sample 2 is the check. NOT_A_RULE moved from 51.7% to 49.7%, which is inside the range. The share of real rules that a hook or a setting could enforce was 101 of 145 (69.7%, plus or minus 7.5) in sample 1 and 100 of 151 (66.2%, plus or minus 7.5) in sample 2. Pooled, that is 201 of 296, or 68%.

The claim we make is this: about two thirds of real rules could be enforced by a hook or a setting. Could is not does. This counts what is possible, not what is installed.

As a control, a second model (Opus) relabeled the first 40 lines of sample 1. It gave the same label on 32 of 40, or 80%.

What this does not show

  • The sample leans toward repos that have settings. Hook shares are likely overstated for CLAUDE.md files in general.
  • The analyzer matches keywords. It is not a parser, so it can miss rules and count lines that are not rules.
  • One repo per organization. Large organizations count once, and the repo we got may not be their main one.
  • The labels come from a model, and each share has a range. A different model could label differently.
  • No person checked the labels line by line.
  • A rule that could be enforced is not a rule that someone should enforce. Some of these are better left to judgment.

The data

Download data.csv One row per organization, 667 rows. Columns:

  • login: the GitHub organization.
  • repo: the repo we read.
  • rules_file: the rules file name we found.
  • bytes: size of that file.
  • has_settings, has_settings_local: 1 if the repo has .claude/settings.json or settings.local.json.
  • has_hooks_dir: 1 if the repo has a hooks directory.
  • hook_events: the hook event names set in the settings.
  • n_hook_commands: how many hook commands the settings define.
  • has_permissions_deny, has_permissions_allow, has_model: 1 if the settings set that key.
  • settings_invalid: 1 if the settings file did not parse as JSON.
  • has_claude_workflow: 1 if the repo has a Claude workflow file.
  • n_total: rule like lines the analyzer found.
  • n_deny, n_nudge, n_setting: lines matched to a deny hook, a nudge hook or a setting in the free kit.
  • n_prose: lines with no match.
